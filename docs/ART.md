# Shipped art

Since Nov 1, 2026 the game ships pictures painted with a local image model, reduced to small pixel-art files. This file says what shipped, how it was made, and how to add or redo pictures.

## Licence status

Resolved Nov 1, 2026: owner holds approval from Alibaba/Qwen for use of Qwen-Image 2.1 outputs. Nov 2, 2026 (v1.0): the owner confirmed the approval also allows open reuse, so all shipped art, painted or code-drawn, is released under CC BY 4.0.

Background, for the record: the ComfyUI workflow uses `qwen_image_2.1_bf16.safetensors` (with `qwen_image_2.1_vae_bf16.safetensors` and the `qwen3vl_8b_w4a8` text encoder). Qwen-Image 2.1 is published under the Qwen Research License (sections 1(i) and 2(a): non-commercial, research or evaluation use), not Apache-2.0 (earlier Qwen-Image releases and 2512 are Apache-2.0). The approval means the pictures may be published. The model itself is not bundled. `src/data/licenses.js` lists it as "used under permission from the licensor". Note: `src/data/licenses.js` is otherwise generated by `scripts/licenses.mjs`; running that script overwrites the Qwen entry, so re-add it (or add it to the script) after regenerating.

Every manifest entry carries `model: 'qwen-image-2.1'`, so a future model swap can find what to redo.

### Manifest ids (`src/data/art.js`)

`ART[id] = { src, w, h, category, model, time, alt }`. Helpers: `art(id)`, `artFor(id, time)`, `artByCategory(category)`, `ART_IDS`.

`time` is `'night'`, `'day'`, `'dawn'` or `'any'` (icons, portraits, creatures).
`artFor(id, time)` returns the `<id>-day` picture for `'day'` or `'dawn'` when one exists and falls back to the plain (night) id.

## How it was made

1. `tools/asset-studio/studio.py` (older drafts) and `tools/asset-studio/gen.py` (new scenes and creatures) paint with ComfyUI. All prompts, seeds, sizes and steps are in `tools/asset-studio/art-jobs.json` (new set) or `out/<category>/plan.json` (older drafts).
2. `tools/asset-studio/day.py` makes the day and dawn scenes. Each is an edit of the full-size night render: the night picture goes into the reference-image input of the Qwen-Image 2.1 text encoder with an edit prompt, so the layout and objects stay the same and only light, sky and colour change. Settings (0.28 megapixels, 15 steps, reference shrunk to 720 px wide, about 70 s per picture on the RX 7900 XTX) and the source night id of each day picture are in `art-jobs.json` under `day`. The first five day pictures were made at 0.6 megapixels and 24 steps (about 190 s each).
3. `tools/asset-studio/ship.py` picks, downsizes (box filter), quantises (no dithering), saves an optimised PNG (WebP lossless if at least 15 percent smaller) and regenerates `src/data/art.js`.

Contact sheets: `tools/asset-studio/out/shipped-sheet.png` (everything shipped) and `tools/asset-studio/out/day-night-sheet.png` (night left, day right).

## Add or change a picture

1. New picture: add a job to `JOBS` in `gen.py` (or a row in `DAYS` in `day.py`), run `python tools/asset-studio/gen.py --only <prefix>`. Only one heavy model may run at a time: unload LM Studio first (about 20 GB of RAM).
2. Add one row to `SHIP` or `NEWROWS` in `ship.py` (id, source, category, alt text). Set the seed you prefer in `PICK`.
3. `python tools/asset-studio/ship.py --sheet`. The script prints per-category sizes and warns when the 5 MB budget (5120 KB) is exceeded.
4. `npm run build:single` and check the picture appears.

Alt text is plain language, no em dashes. Item, quest and achievement ids are permanent, but art ids are not saved data, so they can change with the code that uses them.

## Redo the whole set with a different model

Only the model file names in the ComfyUI workflow (`comfy_qwen_workflow.json`: `UNETLoader`, `CLIPLoader`, `VAELoader`) need swapping, plus the text encoder node type if the new model does not use `TextEncodeQwenImage21`. Move the old PNGs in `out/new/` and `out/day/` aside, run `gen.py`, pick seeds in `ship.PICK`, run `day.py` (it needs a model that accepts reference images; otherwise set `METHOD = "img2img"` with a denoise near 0.6), run `ship.py`, and change the `model` string in `ship.py`.

## Painted scenes that move (started Nov 6, 2026)

Owner request: use image-model pictures for the animated screens, at a higher, face-like pixel density. Pilot: the
Undercroft entrance. No video is generated. Each scene is two matching stills, `lit` (every lamp burning) and `dark`
(lamps out), sharing one palette. The game draws `dark`, then shows `lit` through a flickering, dithered light mask
(`src/pixel/painted.js`), so the light moves over the painted stone. Code flames, mist and dust sit on top
(`drawEntrancePainted` in `src/ui/Crypt.jsx`). If no painted scene ships, the code-drawn scene shows as before.

- **Pixel density:** the same as the painted faces, about 4 image pixels per art pixel (`pixel` in `SCENES`). The tool
  checks for an exact pixel grid first; image-model pictures usually have none. Paint at about 2 MP for scenes roughly
  470 art pixels wide. The picture's shape is free (16:9 by default).
- **Colours:** up to 96. 84 are picked by area and 12 are kept for the brightest spots, so small lamps and windows keep their glow.
- **Reading the picture:** `motion.py` finds the light sources (what is brighter in `lit` than in `dark`) and the
  small bright warm spots (flames), and writes their positions into `src/data/scenes.js`. The game animates
  exactly those spots. If there is no painted dark version, the tool makes a darker copy and every flame becomes a
  flickering light.
- **Rules:** this art is shown only outside study and recall (the entrance is never mounted during a floor). With
  reduced motion it shows one still frame. The canvas pauses when it is off screen or the tab is hidden. Scene
  pictures count toward the 5 MB art budget (`ship.py` and `motion.py` both report the total).

```
python tools/asset-studio/motion.py guide                  # code-drawn entrance -> guides/crypt_entrance.png (no model)
python tools/asset-studio/motion.py paint --seeds 2        # image model: lit from the guide, dark as an edit of lit
python tools/asset-studio/motion.py ship --seed s0         # reduce, read lights/flames, ship, write src/data/scenes.js
python tools/asset-studio/motion.py ship --seed out/new/event_undercroft_entrance_s0.png --dark derive   # any painted picture
python tools/asset-studio/motion.py standin                # stand-in from the guide, to test code without the model
python tools/asset-studio/motion.py gif                    # out/motion/<id>.gif, recorded from the real game code
```
The review sheet `out/motion/<id>_sheet.png` shows the guide, lit, dark, the lights and flames found, and a face
picture at the same zoom for comparing pixel size. Prompts and seeds go into `art-jobs.json` under `motion`.

## Faces for the Names-and-Faces drills (owner chose image-model faces, Nov 2, 2026)

Pipeline (`tools/asset-studio/`): `people.py` builds a balanced cast from a recipe (heritage, skin tone, age band, build, height, features,
marks, asymmetries, piercings, accessories, clothes). `people_llm.py` has the local Qwen write each description; a code check keeps every
trait and rejects invented accessories. `faces.py --cast` paints each original, a look-alike stranger (painted fresh from the same recipe with
new eyes, shape and colour, plus one more feature, and a different seed) and a new look (an edit of the original: new hair or headwear plus
glasses, piercings or clothes). `facecheck.py` has Qwen check gender, age band, a complete face and that a new look is the same person;
`--reject` deletes failures so the next `faces.py --cast` repaints them. `face_sheet.py --cast` makes the review sheet. Speed settings were
timed and compared by eye (`docs/review/face-speed-compare.png`): an original about 11 s, an edit about 40 s, no visible loss at 96 px.

Rules for release: a look-alike must have a clearly different face (never the same eyes) and must not be told apart by clothes, so it wears
the same outfit only about half the time; clothes and hair are changeable features in both directions.

### Idea, not built: face templates (parts that combine)

Asked by the owner: paint sets of parts (eyes, noses, mouths, ears, brows, face shapes) with Qwen and combine them into new faces.
- For: thousands of faces from a small library, a few KB per part; exact control for the drills (a look-alike swaps exactly the eyes
  and one more part, nothing else); every face is reproducible from its list of parts.
- Against: pasted pixel-art parts tend to look stuck on unless pose, scale, lighting and skin tone match exactly. Skin tone and age change
  how every part should look, so each part needs recolouring per skin ramp and ageing variants; heritage changes face structure, not just parts.
- A workable version: (1) paint one neutral front-facing "base head" per face shape, skin tone and age band with a fixed camera and light,
  (2) paint parts on the same base with Qwen edits ("change only the eyes to ...") so they share pose and light, (3) cut each part with a
  mask from the base-versus-edit difference, (4) store parts as palette-indexed sprites recoloured to the base's skin ramp, (5) composite at
  96 px and blend seams with one shading pass. Hair, headwear and clothes stay whole layers.
- Suggested test before committing: 2 base heads x 6 eye sets x 6 noses x 6 mouths, judged on a sheet against whole paintings. If the
  composites read as natural, they can grow the pool and generate look-alikes exactly; if not, whole paintings stay the release method.

Count and time at the fast settings: 5 scenes and 13 small pictures, 2 seeds each = 36 pictures, about 26 minutes; 7 day or dawn pictures, about 8 minutes.

`tools/asset-studio/picreview.py`: a Qwen vision review of every shipped picture except faces (130 now). It flags pictures that do not look like pixel art, whose alt text in `src/data/art.js` does not match, that show readable text or logos, that look like a copied character, or that look scary. `--dry` lists what it would check, `--limit N` checks the first N, `--drafts` checks the new unshipped drafts instead. Output: `out/picreview/report.json` and `report.md` (`drafts.json` and `drafts.md` for drafts), problems first. The model's flags are hints for a human look, not verdicts.

`tools/asset-studio/after_faces.py`: a chain runner for after the face run. It waits for `cast_run.py` (the log says `ALL DONE` and no such python process is left), frees LM Studio and ComfyUI models, paints the new jobs, makes the trial and vigil day pictures, reviews with Qwen, and writes `docs/review/new-art-sheet.png` and `new-art-sprites-sheet.png`. It does not paint faces 150 to 299 and does not run `ship.py`. `--dry` prints the plan; the log with timings is `out/after_faces.log`.

Budget estimate: the new pictures add roughly 200 KB (5 scenes at about 16 KB, 7 day or dawn pictures at about 12 KB, 13 sprites at about 2.5 KB), so the non-face art goes from about 0.9 MB to about 1.1 MB, well inside the 5 MB (5120 KB) budget that the faces mostly use.
